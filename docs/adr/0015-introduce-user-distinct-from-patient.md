# Introduce User as distinct from Patient

Patient (who receives care) and User (who books) are split into two concepts. A single User can manage several Patient profiles — themself plus, for example, their children — rather than every Patient needing their own separate login. Registering as a User auto-creates a Patient profile representing the User themself, so the common case (someone booking for themself) needs no extra step. This retires "Akun Pasien" as a term: it named a phone+OTP credential tied 1:1 to one Patient, which no longer fits once one account can hold several Patients.

Registration only requires phone number verification via OTP; email is collected but can be verified later, and a password is never required at registration — a User sets one later only if they want the email+password login option, and a Google SSO signup never needs one at all. This keeps signup as low-friction as the existing guest booking flow's phone+OTP step, rather than forcing every new User through a heavier form up front. Google SSO still requires phone verification separately, since phone is the channel for WhatsApp OTP and Appointment reminders elsewhere in the Platform — but that verification can be deferred to the User's first Appointment instead of blocking the SSO signup itself.

Because Booking Source (`online`/`phone`) only records the channel, an Appointment also needs Booked By — the actor who created it: a guest Patient (self-service, no User account), a User (booking for one of the Patients they manage), or a Resepsionis (phone booking). Two `online` Appointments can be Booked By different kinds of actor, so Booking Source alone can't answer "who acted here" — Booked By is also the natural place to hang the audit trail (story #46) for who created or changed an Appointment.

The existing guest booking flow (phone+OTP validating a single booking, no persistent account — already built in the patient mobile booking prototype) is unaffected: becoming a User is optional, never required to book.
